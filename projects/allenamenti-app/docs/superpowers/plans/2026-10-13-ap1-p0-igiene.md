# AP1 P0 — Igiene: piano di implementazione

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Esecuzione di questo piano: in sessione** (superpowers:executing-plans). I Task 1 e 4 toccano credenziali e produzione, che per regola (spec §3.2) non si delegano ai subagent. Il Task 5 richiede Fabrizio (prova manuale e primo push).

**Goal:** mettere in ordine repo, dipendenze e storico migration, e pubblicare su `main` (push P0) senza cambiare il comportamento dell'app.

**Architecture:** quattro interventi indipendenti su `main`, ognuno col suo commit. Poi un unico cancello (build e prova manuale del flusso Live) e il primo push, che fa Fabrizio. Lo schema del database non cambia: si tocca solo la tabella dello storico migration.

**Tech Stack:** Next.js 16 (App Router), Capacitor 8 (iOS via SPM), npm, Supabase (MCP: `list_migrations`, `execute_sql`), git.

**Spec:** `docs/superpowers/specs/2026-10-13-ap1-igiene-fase2-design.md`, §3 e §4.

## Global Constraints

- Si lavora su `main` in locale. Nessun push prima del Task 5.
- Versioni: `next` **16.3.8**; `@capacitor/core`, `@capacitor/cli`, `@capacitor/ios` **8.5.2**; `npm audit fix` **senza** `--force`.
- Il primo push lo fa Fabrizio con `! git push`, inserendo un token GitHub fine-grained nuovo (solo questo repo, con scadenza). Il token non va mai nell'URL del remote né in chat.
- Mai leggere né stampare chiavi, token o password, compreso `.env.local`. Per le verifiche si usano solo conteggi.
- Il progetto Supabase `lzwyhokkvzxlnubsenmf` è la produzione: niente operazioni distruttive. Prima di toccare lo storico migration si salva l'output di `list_migrations`.
- Non toccare `data.json`, `backups/` e `config.json` (non versionati). Non committare `next-env.d.ts` né `.claude/settings.local.json` (modifiche locali o rumore generato).
